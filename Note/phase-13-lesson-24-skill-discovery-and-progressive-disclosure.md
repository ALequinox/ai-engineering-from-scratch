# 第 13 阶段 · 第 24 课：技能发现与渐进式披露

- 学习日期：2026-09-30
- 原课程：[Skill Discovery and Progressive Disclosure](../phases/13-tools-and-protocols/24-skill-discovery-and-progressive-disclosure/docs/en.md)
- 学习目标：把候选发现、目录发布、正文激活和按条件读取资源分开，并能解释冲突、预算与路径边界。
- 本课结果：运行课程演示，完成[四阶段追踪](../agent-skills-first-run/discovery-trace.md)；23 个测试通过；六题测验 6/6。

## 1. 为什么要渐进式披露

若主机装有许多技能，开场就载入所有正文、参考文件、脚本和素材，会让无关内容占据上下文。完全不提供目录，又要求用户记住每个技能的路径。因此先发布足够选择的简短元数据，选中后再加载正文，走到具体分支才加载对应资源。

```mermaid
flowchart LR
    A[发现候选] --> B[校验与解决冲突]
    B --> C[发布目录元数据]
    C --> D[激活选中 SKILL.md]
    D --> E[按任务读取参考文件]
```

这五个动作需要分别观察。目录里出现某技能，不表示它的正文已经进入模型上下文；正文激活，也不表示包内所有参考文件已经读取。

## 2. 发现范围与同名冲突是主机策略

发现时扫描主机配置的范围，例如项目、用户、管理员、插件或内置位置。可移植的技能格式规定包的结构，**不规定统一的安装路径与范围优先级**。发现适配器要记录扫描范围、候选来源、校验失败、同名冲突以及最终发布项。

课程实验明确声明 `project > user`。它发现三个候选：

- `project/evidence-report`
- `user/evidence-report`
- `user/meeting-brief`

同名冲突由项目范围的 `evidence-report` 胜出，用户范围的同名项被记录为遮蔽；`meeting-brief` 仍进入目录。如果两个同名候选**优先级相同**，课程代码报歧义，不能依赖偶然的文件枚举顺序。换一台机器或改变目录顺序不应悄悄改变选中的技能。

## 3. 三层上下文开销分别计算

1. **Level 1：目录元数据。** 发布名称、描述、范围和来源等路由所需信息，不加载所有正文。演示的模型可见目录为 **461 字符**，包含两个条目。
2. **Level 2：选中技能的正文。** 选择项目范围的 `evidence-report` 后才调用 `load_skill_body`，读取 **70 字符**；另一个技能正文仍未加载。
3. **Level 3：当前分支需要的资源。** 处理报告格式时才读取所选技能的 `references/format.md`，为 **46 字符**；没有因目录发布而预读其他资源。

完整诊断报告为 **607 字符**，它包括冲突、遗漏和预算等信息；不能把它与 **461 字符的模型可见目录**混为一谈。目录预算和激活后正文、资源的预算也应分别衡量。

`references/` 通常是按需阅读的说明或数据；`scripts/` 是通过获准工具执行的确定性程序；`assets/` 是模板、样例或其他素材。这些目录名是组织约定，不会自行授予文件或执行权限。

## 4. 按分支链接，避免“全部都读”

入口正文应直接指出哪种条件对应哪份参考文件，例如“生成报告格式时，读取 `references/format.md`”。只写“需要时阅读 references 目录”会迫使模型猜测，也可能让它把所有文件都读进上下文。

本课的[追踪文件](../agent-skills-first-run/discovery-trace.md)把四步分开记录：发现三个候选、目录发布两个条目、激活一个正文、按报告格式分支读取一个参考文件。这份文件是课堂的可观察检查点。

## 5. 目录预算与可审计的遗漏

目录太大时，主机需要按声明的条目数、描述长度和序列化大小做**确定性**限制，并在诊断中记录被缩短或省略的技能。这样相同输入可以复现相同目录；需要被省略的技能时，可缩小搜索范围再发现。每次随机抽样会让路由难以解释和复查。

课程代码的 `CatalogBudget` 分别管理最大条目数、单条描述长度和模型可见目录大小。它测量的是实际序列化的目录，而不把字符数误称为通用 token 数。

## 6. 资源路径也是边界

课程示例只允许包根目录中的文件，或一个直接子目录中的文件。因此 `references/schema.md` 符合该示例契约，`references/archive/schema.md` 太深，应拒绝。绝对路径、`..` 路径穿越、反斜杠和可能指向包外的符号链接也要拦截；先解析路径，再确认最终目标仍在已解析的包根目录内。

路径留在包内只证明**位置**符合规则，不证明文件**内容**可信。即使合法的参考文件也可能包含恶意指令；后续信任课程再处理内容边界。

## 7. Build It 与实际运行

`code/main.py` 实现 `discover_scope`、`resolve_collisions`、`build_catalog`、`load_skill_body` 和 `load_reference`。发现时只看直接子目录和必要的 frontmatter，避免把一个技能包内部的示例文件误当成独立技能。课程的 frontmatter 解析器只实现实验需要的标量子集，不等于完整 YAML 解析器。

从课程目录运行：

```bash
cd phases/13-tools-and-protocols/24-skill-discovery-and-progressive-disclosure
python3 code/main.py
python3 -m unittest discover -s code/tests -v
```

演示退出码 0，输出项目范围胜出、目录两项、`omitted: []`、461/70/46 三层字符数。23 个单元测试通过，覆盖范围优先级、同名歧义、预算、正文延迟加载以及路径穿越和符号链接拒绝。演示使用临时目录并在结束时清理；本课没有安装 `outputs/` 中的技能包。详细运行记录在[学习进度](../AGENT-SKILLS-LEARNING.md)。
