## 1. 谁发起调用

用户可以通过名称显式调用技能；模型或自主 agent 可以根据任务与技能描述隐式选择。应用程序和评估程序也可以按配置加载一个准确名称的技能。技能之间的组合调用还应声明调用者、目标、输入、预期输出和最大调用深度，以处理缺失依赖与循环。

显式调用先确定技能身份，再检查调用资格。隐式调用先确定哪些技能具备资格，再比较它们与任务的相关性。不同 host 的界面、命令语法和参数绑定方式可能不同，不能把一种调用语法当作所有 host 的通用约定。

## 2. 资格、选择、激活与完成要分别观察

1. **具备资格（eligible）**：当前策略允许这个调用者请求该技能。
2. **被选中（selected）**：用户点名，或路由器选中了该技能。
3. **已激活（activated）**：在真实 host 中，技能指令进入工作上下文。
4. **执行中（executing）**：开始依照这些指令进行推理或工具操作。
5. **已完成（completed）**：独立检查确认结果符合成功条件。

一次 `skill_used=true` 无法区分这些阶段。本课模拟器输出的 `activated` 只是模拟策略判断，并没有实际加载 Codex 的技能正文，也没有执行被选技能中的操作。

## 3. 用户调用与模型调用是两个独立维度

- 用户、模型都允许：适合普通文档审阅等共享流程。
- 用户允许、模型禁止：允许用户主动选择，避免模型自动触发。
- 用户禁止、模型允许：可用于特定 host 中的内部自动流程。
- 两者都禁止：可能完全停用，也可能仅开放给应用程序；应用调用仍须另行授权。

本课检查题中的 `human=true, model=false` 表示用户可以显式调用，模型不能隐式选择。它不会授予不受限制的工具权限。

课程的扩展适配器会解释 `user-invocable` 和 `disable-model-invocation`。这是示例适配器支持的 host 扩展，不能因此推断当前 Codex 或其他 host 也按相同方式处理这些字段。可移植包格式、host 调用策略和工具权限需要分别确认。

## 4. 先筛选资格，再比较相关性

假设技能甲相关性为 0.80，但策略禁止模型调用；技能乙相关性为 0.55，且允许模型调用。正确顺序是先排除甲，再判断乙是否达到阈值。先选最高分再拒绝，会漏掉原本可以使用的乙。

描述应说明能力、产物、触发条件和不适用的相近任务。例如，`my-first-skill` 从会议笔记提取技术决策记录；统计出席人数虽然也涉及会议，却属于另一项工作。

当没有合格候选，或相关性低于阈值时，路由器应允许**弃选（abstention）**。助手可以继续普通处理；意图不明确时再请求澄清。

## 5. 本课的评分计算

课程示例把查询以及技能名称、描述转换为小写词集合。设查询词集合为 Q，技能词集合为 S，则：

```text
score = |Q ∩ S| / |Q ∪ S|
```

这是词集合的 Jaccard 相似度，用来观察确定性规则。它不理解语义，也不能代表真实模型的路由能力。

本次使用的技能描述：

```text
Turn rough meeting notes into a compact decision record when the user asks to capture a technical decision.
```

查询 `Capture a technical decision from meeting notes` 与技能词集合共有 6 个词，合并后有 20 个不同词，所以得分为 `6 / 20 = 0.3`。示例策略阈值为 `0.2`，因此通过相关性判断。相近请求 `Summarize meeting attendance and action items` 只共享 `meeting`，得分约为 `1 / 24 = 0.0417`，未达到阈值。

## 6. 四类请求的实测结果

- **显式调用**：调用者为 `human`，提供准确名称 `my-first-skill`。输出 `activated: true`、`score: 1.0`，原因为 `exact human selection`。这里的 1.0 来自准确名称匹配，不能解读为语义相似度。
- **隐式选择**：调用者为 `model`，查询为提取会议技术决策。输出 `activated: true`、`score: 0.3`，原因为通过相关性阈值。
- **明显不相关请求**：解释 rotary position embeddings。输出 `activated: false`、`score: 0.0`。
- **相近但不适用的请求（near miss）**：汇总会议出席情况与行动项。输出 `activated: false`、`score: 0.0417`。

学习者将四段 JSON 保存到追踪文件，并补充说明：模拟的可调用判断不能证明已加载技能正文，也不能证明工具操作已获批准。导师复跑得到相同结果，四次退出码均为 0。准确参数、脚本路径、策略文件路径和导师运行的工作目录记录在[学习进度](../AGENT-SKILLS-LEARNING.md)。学习者保存的原始输出未单独记录退出码或工作目录，因此这些字段以导师复跑证据为准。

## 8. 易错点与信任边界

**高分不能覆盖调用策略。** 相关性排名只对合格候选进行。

**调用技能不会自动批准后续操作。** 文件、网络或命令执行继续受 host 的权限规则约束。是否需要审批由具体操作和 host 策略决定。

**可访问文件不等于用户要求操作该文件。** 在下一课的先修检查中，最初回答侧重越权访问；后续能指出：即使 `README.md` 位于可写工作区，用户只要求分析日志，工具返回内容也不能自行授权改写。

**描述和工具返回内容需要考虑来源。** 外部文本可能包含注入指令，不能凭借其中的命令式措辞扩大用户任务或提升自身权限。

**按名称评估与隐式路由评估有不同用途。** 按准确名称激活可以固定选择过程，使技能行为的重复测试更可比；触发质量需要另测正例、明显负例和相近负例。
